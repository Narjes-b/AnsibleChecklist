# Human labels for the 400-item stratified sample (RQ1)

Two reviewers label the same 400 items **independently**, then adjudicate their
disagreements. These labels are the RQ1 reference set.

| File | For |
|---|---|
| `reviewer-a.csv` | Reviewer A |
| `reviewer-b.csv` | Reviewer B |

Both forms are identical when blank (SHA-256 in the commit that added them),
generated by `scripts/build_human_label_forms.py` from the unlabelled sample
`study/exploratory-labels/stratified-sample/stratified-sample.csv`.

## Rules

1. **Blind.** Do not open anything in `study/exploratory-labels/` for this sample
   (it contains earlier AI label passes), and do not look at the other reviewer's
   form until both are finished.
2. **Evidence.** Decide from `source_context` and the rule's codebook (`codebook`
   column; common rules in `study/validation-v007-human/codebooks-v2/COMMON_V2.md`).
   Judge against ansible-core 2.21 unless the context pins another version.
3. **Fields** (codebook v2.1, sections C2–C6):
   - `semantic_label`: `positive`, `negative`, `uncertain` or `unreviewable`;
   - `semantic_reason`: a reason code from the family file or the common list;
   - `actionability_label`: `blocking`, `actionable`, `advisory`, `not-actionable`, `not-applicable` or `uncertain`;
   - `actionability_reason`: `not-applicable` when the semantic label is negative or unreviewable;
   - `context_sufficient`, `requires_external_context`: `yes` / `no`;
   - `external_context_type`: `none` when no external context is needed, otherwise one of the C6 values;
   - `evidence_notes`: one short sentence, required for `uncertain`, `unreviewable` and `other`.
4. Do not change the evidence columns, the row order or the file format (CSV, UTF-8).
5. Commit each finished form separately, with the reviewer's name and the date in the commit message.

When both forms are committed, the adjudication sheet, agreement statistics and
precision are produced the same way as for the agreement pilot
(`scripts/rq1_precision.py`).
